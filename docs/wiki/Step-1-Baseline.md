## What was done

Before any code, the project got its plan: a Business Case (`BC-001`), a
Stakeholder Analysis (`SA-001`) with S01 to S03, and a Project Plan
(`PP-001`) that splits the work into six milestones, `MIL-001` to
`MIL-006`. Each milestone has Go/No-Go criteria, a task list and its own
branch and pull request.

## What was gained

- The assignment text is short, but writing the Business Case turned it into
  measurable success criteria: ten colours, HEX codes, a share in percent, and
  the limits of an upload.
- Naming the readers (S02 course participants, S03 repository visitors) decided
  what the README needs: setup, run and test commands, and no runtime
  dependencies beyond what the task needs.
- Splitting the work into milestones with one branch each makes the history
  readable: every step of this wiki is one pull request.
- A plan is a decision record. Questions such as "which web server?" are written
  down as assumptions now and answered by an ADR in the Design step.
